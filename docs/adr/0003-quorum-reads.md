# Linearizable reads ask a majority, not the log

A read barrier used to be an entry proposed through the log: one consensus slot and a durable write at a majority of recorders per read batch, which held `kv-tokio`'s linearizable reads to a third of etcd's in the comparison (`docs/benchmarks.md#against-etcd`). etcd reads through ReadIndex, which needs a leader that confirms it still leads, and lease reads need bounded clocks; QuePaxa has neither a stable leader nor a clock assumption. So a read asks recorders for their high-water mark (the first slot past every slot they hold state for, from memory: registers, decided log, snapshot floor), takes the largest answer K from a majority of every member set from the decided prefix on, and is ready once its replica applied every slot below K. A completed write's slot was recorded durably by a majority of its members, which the read's majority meets, so K is past it (PQR, Charapko et al., HotStorage 2019; the reader's role moves into the replica). Answers are not gated on durability: the mark in memory is never below the durable one, and a mark too high only makes the read wait for a slot that takeover decides. Covering every member set from the prefix on, not only the newest, is what keeps a replica that learns several changes at once from missing an intermediate epoch's writes. `Reads.tla` models the rule with crashes, compaction and membership changes; `ReadsProof.tla` proves it for fixed membership. The log barrier remains only for a retiring replica, which needs every change decided before it applied.
